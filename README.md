# KKU Connect 🏫

เว็บไซต์รวมข่าวสารของ**มหาวิทยาลัยขอนแก่น** แยกตามคณะ/วิทยาลัยทั้งหมด ที่**อัปเดตอัตโนมัติ** — ดึงหัวข้อข่าวจากแหล่งที่เชื่อถือได้ แสดงผลในดีไซน์ของเราเอง และลิงก์กลับไปอ่านฉบับเต็มที่ต้นทาง

> ออกแบบตามเอกสาร KKU CONNECT (ปัญหา: นักศึกษาพลาดข่าวสารสำคัญเพราะข้อมูลกระจายหลายช่องทาง → รวมไว้ที่เดียว กรองตามคณะได้)

## แหล่งข่าว

ดึงจาก 2 ทางประกอบกัน:

1. **RSS ทางการของเว็บคณะ** (คณะที่เปิดใช้: วิทยาศาสตร์ · ศึกษาศาสตร์ · ทันตแพทยศาสตร์ · สถาปัตยกรรมศาสตร์ · บริหารธุรกิจและการบัญชี · ศิลปกรรมศาสตร์ · วิทยาลัยการปกครองท้องถิ่น) — ได้ข่าวตรงจากคณะพร้อม**รูปประกอบ**
2. **Google News RSS** รายคณะ (ค้นด้วยชื่อคณะ + "มหาวิทยาลัยขอนแก่น") สำหรับคณะที่เหลือและข่าวจากสำนักข่าวภายนอก

ทุกคณะมีปุ่มลิงก์ไป**เว็บไซต์คณะ**และ**เพจ Facebook ทางการ**ในหน้าเว็บ (Facebook ไม่เปิดให้ดึงโพสต์อัตโนมัติ จึงลิงก์ไปที่เพจโดยตรง)

ครอบคลุม **คณะ/วิทยาลัยทั้งหมด 24 แห่ง** ของ มข. + ข่าวรวมระดับมหาวิทยาลัย:

แพทยศาสตร์ · วิศวกรรมศาสตร์ · วิทยาศาสตร์ · เกษตรศาสตร์ · ศึกษาศาสตร์ · พยาบาลศาสตร์ · มนุษยศาสตร์และสังคมศาสตร์ · ทันตแพทยศาสตร์ · เภสัชศาสตร์ · เทคนิคการแพทย์ · สาธารณสุขศาสตร์ · สัตวแพทยศาสตร์ · เทคโนโลยี · สถาปัตยกรรมศาสตร์ · บริหารธุรกิจและการบัญชี · ศิลปกรรมศาสตร์ · นิติศาสตร์ · เศรษฐศาสตร์ · สหวิทยาการ (หนองคาย) · วิทยาลัยการคอมพิวเตอร์ · วิทยาลัยการปกครองท้องถิ่น · วิทยาลัยนานาชาติ · บัณฑิตวิทยาลัย · วิทยาลัยบัณฑิตศึกษาการจัดการ

เพิ่ม/แก้แหล่งได้ที่ตัวแปร `FACULTIES` ใน `fetch-news.mjs`

**เว็บนี้คัดเฉพาะข่าวที่มีประโยชน์ต่อนักศึกษา** — หัวข่าวต้องเกี่ยวกับ นศ./ทุน/การรับเข้า/กิจกรรม/ฝึกงาน-สายอาชีพ/บริการนักศึกษา จึงจะแสดง ข่าวองค์กร ข่าวคดี ข่าวการเมือง และ PR ผู้บริหารถูกกรองออกอัตโนมัติ (ดูกติกาที่ `STUDENT_KEEP` และ `EXCLUDE_RULES` ใน `fetch-news.mjs`)

## ฟีเจอร์หน้าเว็บ

- **ติดตั้งเป็นแอปได้ (PWA)** — มี `manifest.json` + `sw.js` ครบ Chrome/Android จึงขึ้นเมนู "ติดตั้ง / เพิ่มไปยังหน้าจอโฮม" เปิดแล้วเป็นหน้าต่างแยกไม่มีแถบที่อยู่ของเบราว์เซอร์ และ**เปิดอ่านข่าวเก่าตอนไม่มีเน็ตได้** (สร้างไอคอนใหม่ด้วย `node make-icons.mjs`)
- **ดีไซน์ตาม wireframe ใน KKU CONNECT.pdf** — หน้าแรก (สไลด์ข่าวเด่น + แนะนำสำหรับคุณ + ข่าวสารล่าสุด + กล่องข่าวสารคณะของผู้ใช้) และหน้ารายละเอียดข่าวพร้อม**กล่องสรุปข่าวโดย AI** (สรุปจำลองจากหัวข่าว/หมวด/วันที่ ไม่ได้เรียก AI จริง) + **AI แนะนำข่าวที่เกี่ยวข้อง** + ปุ่มแชร์ LINE/Facebook/X
- **หมวดหมู่ข่าว 7 หมวด** — ประกาศ · การศึกษา · ทุนการศึกษา · กิจกรรม · รับสมัครงาน · วิจัย · อื่นๆ (จัดหมวดอัตโนมัติจากคำสำคัญในหัวข่าว ดูกติกาที่ `TOPIC_RULES` ใน `fetch-news.mjs`)
- **แยกข่าวตามคณะ** — เมนู "ดูรายคณะ" กดเปิด/ปิดรายชื่อคณะทั้ง 24 แห่ง เลือกแล้วกรองทันที (มือถือเป็นแถบเลื่อนด้านบน)
- **ค้นหา** — พิมพ์ค้นหัวข้อข่าวได้ทุกคณะ
- **บันทึกข่าว / ตั้งเตือน** — กด 🔖 เก็บข่าวไว้อ่านทีหลัง หรือ 🔔 ตั้งเตือนไว้ดูในหน้าการแจ้งเตือน (เก็บใน localStorage ของเครื่อง) ส่วนการกด 🔖 จะถูกส่งไปเก็บเป็น log หลังบ้านด้วย ดูหัวข้อ "หลังบ้าน: log การบันทึกข่าว"
- **การแจ้งเตือน** — หน้ารวมข่าวใหม่ใน 48 ชั่วโมงล่าสุด (กระดิ่งบนหัวเว็บก็เปิดดูได้)
- **ตั้งค่า** — เปิด/ปิดแบนเนอร์, จำนวนข่าวต่อหน้า, เลือกหน้าเริ่มต้น (คณะ/หมวดที่สนใจ), ล้างรายการบันทึก
- **สมัครสมาชิก / เข้าสู่ระบบ** — เก็บชื่อ ชั้นปี คณะ เพศ อีเมล แล้วตั้งหน้าแรกเป็นข่าวคณะของผู้ใช้ให้อัตโนมัติ (รายละเอียดและข้อจำกัดอยู่หัวข้อถัดไป) ส่วนการแจ้งเตือนแบบพุชยังเป็นแผนพัฒนาต่อ

## สมัครสมาชิก / เข้าสู่ระบบ

กดปุ่มโปรไฟล์มุมขวาบน → สมัครด้วย **ชื่อ-นามสกุล, ชั้นปี, คณะ, เพศ, อีเมล, เบอร์โทร และรหัสผ่าน** (ตัวเลือกคณะดึงจากรายการแหล่งข่าวใน `data/news.json` อัตโนมัติ ไม่ต้องมาไล่แก้เอง)

พอสมัครเสร็จ เว็บจะ**ตั้งหน้าแรกเป็นข่าวคณะของผู้ใช้ให้อัตโนมัติ** ทุกครั้งที่เปิดเข้ามา — ตอบโจทย์ Pain Point ในเอกสารที่ว่า "อยากเห็นข้อมูลที่เกี่ยวข้องกับตัวเองเท่านั้น"

เข้าสู่ระบบด้วย **อีเมลหรือเบอร์โทรก็ได้** คู่กับรหัสผ่าน (อีเมลไม่สนตัวพิมพ์เล็ก-ใหญ่ เบอร์จะมีขีดคั่นหรือไม่ก็ได้) **บัญชีเก็บอยู่หลังบ้าน จึงเข้าสู่ระบบจากเครื่องไหนก็ได้**

คนที่ยังไม่สมัครยังอ่านข่าวได้ครบทุกอย่างตามปกติ ไม่มีหน้ากั้น

### ตั้งค่าหลังบ้าน (`accounts.gs`)

1. เปิด [script.google.com](https://script.google.com) → **New project** → วางเนื้อหาไฟล์ `accounts.gs`
2. เลือกฟังก์ชัน `setup` แล้วกด **Run** → ได้ลิงก์ Google Sheets ใน Execution log
3. กด **Deploy → New deployment** → ชนิด **Web app** → Execute as: **Me** → Who has access: **Anyone** → Deploy
4. คัดลอก Web app URL (ลงท้ายด้วย `/exec`) ไปใส่ `ACCOUNTS_WEBHOOK_URL` ใน `config.js`

ทดสอบว่า deploy สำเร็จได้โดยเปิด `<URL>?token=kkuconnect-2569&action=ping` ในเบราว์เซอร์ ควรเห็น `{"ok":true,"pong":true}`

ถ้าเว้น `ACCOUNTS_WEBHOOK_URL` ว่างไว้ ระบบสมาชิกจะปิดทั้งหมด (กล่องสมัคร/เข้าสู่ระบบจะบอกผู้ใช้ตามจริง) ส่วนการอ่านข่าวไม่กระทบอะไรเลย

> `signup-sheet.gs` เป็นเวอร์ชันเก่าที่เลิกใช้แล้ว — ส่งข้อมูลได้ทางเดียว (`no-cors`) อ่านคำตอบกลับไม่ได้ จึงเอามาล็อกอินไม่ได้ ถ้ายัง deploy ค้างอยู่จะลบทิ้งก็ได้ ข้อมูลเก่าในชีตเดิมไม่หาย

### รหัสผ่านถูกเก็บยังไง

ทำสองชั้น:

1. **ในเบราว์เซอร์ผู้ใช้** — แฮชรหัสด้วย SHA-256 ก่อนส่ง รหัสจริงจึงไม่เคยออกจากเครื่องและไม่โผล่ใน URL
2. **ใน Apps Script** — เอาค่าที่ได้มาแฮชซ้ำกับค่าสุ่มประจำบัญชี (salt) ก่อนเก็บลงชีต สองคนตั้งรหัสเหมือนกันก็เก็บคนละค่า

ที่ต้องให้หลังบ้านเป็นคนใส่ salt เพราะผู้ใช้ล็อกอินด้วยอีเมลหรือเบอร์ก็ได้ ถ้าผูก salt กับอีเมล คนที่ล็อกอินด้วยเบอร์จะคำนวณค่าเดิมไม่ได้

> **ข้อจำกัดที่ต้องรู้:** นี่ยังไม่ใช่ระบบยืนยันตัวตนระดับใช้งานจริง — ไม่มี bcrypt, ไม่จำกัดจำนวนครั้งที่ลองรหัสผิด, ไม่มีลืมรหัสผ่าน และค่าแฮชที่ส่งจากหน้าเว็บก็ใช้แทนรหัสได้ถ้าถูกดักระหว่างทาง เหมาะกับการสาธิต/นำเสนอ ถ้าจะใช้จริงต้องต่อ Firebase Authentication หรือ backend อื่น หน้าสมัครจึงมีข้อความเตือนผู้ใช้ไม่ให้ตั้งรหัสซ้ำกับบัญชีสำคัญ
>
> โทเคน `ACCOUNTS_TOKEN` กันได้แค่บอทที่ยิงมั่ว เพราะฝังอยู่ในหน้าเว็บที่ใครก็เปิดดูได้ ถ้าเจอสแปมให้เปลี่ยนโทเคนทั้งใน `config.js` และ `accounts.gs` แล้ว Deploy ใหม่

| ค่าที่เก็บใน localStorage | เก็บอะไร |
|---|---|
| `kkuconnect-session` | ข้อมูลบัญชีที่ล็อกอินค้างอยู่ในเครื่องนี้ (ตัวบัญชีจริงอยู่หลังบ้าน) |
| `kkuconnect-settings` | ตั้งค่าเว็บ รวมถึงหน้าแรกเริ่มต้น (`defaultCat`) |
| `kkuconnect-saved` / `kkuconnect-reminders` | ข่าวที่กดบันทึก / ตั้งเตือนไว้ |
| `kkuconnect-pending-log` | log การกดบันทึกข่าวที่ยังส่งเข้าชีตไม่สำเร็จ รอส่งใหม่ |
| `kkuconnect-device` | รหัสประจำเครื่องแบบสุ่ม ใช้แยกผู้ใช้ที่ไม่ได้ล็อกอินออกจากกัน |


## หลังบ้าน: log การบันทึกข่าว

ทุกครั้งที่มีคนกดปุ่ม 🔖 **บันทึก** เว็บจะส่งข้อมูลไปต่อแถวใน Google Sheets ให้ ทำให้ตอบได้ว่า **ใครบันทึก ข่าวอะไร วันไหน เวลาไหน** — ใช้เป็นข้อมูลประกอบ **ตัวชี้วัดการใช้งานจริง** ได้ และดูได้ว่าข่าวหมวดไหน/คณะไหนคนสนใจมากที่สุด

หนึ่งแถว = การกดบันทึกหนึ่งครั้ง มี 15 คอลัมน์

| คอลัมน์ | เก็บอะไร |
|---|---|
| เวลาที่บันทึก | เวลาฝั่งเซิร์ฟเวอร์ (Google) ใช้เป็นหลัก ผู้ใช้แก้ไม่ได้ |
| ผู้บันทึก | ชื่อ-นามสกุลของสมาชิก หรือ `ผู้ไม่ระบุตัวตน` ถ้ายังไม่ล็อกอิน |
| สถานะผู้ใช้ | `สมาชิก` / `ไม่ระบุตัวตน` |
| อีเมล · ชั้นปี · คณะของผู้บันทึก | ข้อมูลจากตอนสมัครสมาชิก (ว่างถ้าไม่ได้ล็อกอิน) |
| รหัสเครื่อง | รหัสสุ่มประจำเบราว์เซอร์ ใช้แยกว่าเป็นคนละคนกัน แม้ไม่รู้ว่าเป็นใคร |
| หัวข้อข่าว · คณะ/แหล่งข่าว · หมวดหมู่ · วันที่ของข่าว · ลิงก์ข่าว | ข่าวที่ถูกบันทึก |
| เวลาในเครื่องผู้ใช้ | เวลาที่กดจริงในเครื่องผู้ใช้ ต่างจากคอลัมน์แรกได้ถ้าตอนกดเน็ตหลุด |
| บันทึกจากหน้าเว็บ · รหัสรายการ | URL ที่กดมา และรหัสกันข้อมูลซ้ำ |

### วิธีติดตั้ง (ราว 3 นาที)

1. เปิด [script.google.com](https://script.google.com) → **New project** → วางเนื้อหาไฟล์ `save-log.gs` (คนละโปรเจกต์กับ `accounts.gs`)
2. เลือกฟังก์ชัน `setup` แล้วกด **Run** → ได้ลิงก์ Google Sheets ใน Execution log
3. กด **Deploy → New deployment** → ชนิด **Web app** → Execute as: **Me** → Who has access: **Anyone** → Deploy
4. คัดลอก Web app URL (ลงท้ายด้วย `/exec`) ไปใส่ `SAVELOG_WEBHOOK_URL` ใน `config.js`

ทดสอบว่า deploy สำเร็จได้โดยเปิด URL นั้นในเบราว์เซอร์ ควรเห็น `{"ok":true,...,"rows":0,...}` (`rows` คือจำนวน log ที่เก็บไว้แล้ว)

### รายละเอียดที่ควรรู้

- **ยังไม่ได้ตั้งค่า = ไม่มีอะไรเปลี่ยน** ถ้าเว้น `SAVELOG_WEBHOOK_URL` ว่างไว้ ปุ่ม 🔖 ทำงานเหมือนเดิมทุกอย่าง เพียงแต่ไม่ส่งข้อมูลออกจากเครื่องผู้ใช้เลย
- **เก็บเฉพาะตอนกดบันทึก** การกดซ้ำเพื่อเอาออกจากบันทึกไม่ถูกเก็บ (คุยกันไว้แบบนี้ — ถ้าอยากได้ด้วยภายหลังเพิ่มได้)
- **เน็ตหลุดไม่หาย** log เข้าคิวใน `localStorage` ก่อนส่งเสมอ ส่งไม่ออกก็ลองใหม่ตอนเปิดเว็บครั้งหน้า และฝั่ง Apps Script เช็ค `รหัสรายการ` ซ้ำให้ จึงไม่มีแถวซ้ำในชีต
- **บอกผู้ใช้ตามจริง** หน้า **ตั้งค่า → ข้อมูลของฉัน** จะขึ้นข้อความบอกว่ามีการเก็บสถิติการกดบันทึกไว้ (ข้อความเปลี่ยนตามว่าล็อกอินอยู่หรือไม่) และจะไม่ขึ้นเลยถ้ายังไม่ได้ตั้งค่า `SAVELOG_WEBHOOK_URL`
- **โทเคนกันได้แค่บอท** `SAVELOG_TOKEN` ฝังอยู่ในหน้าเว็บที่ใครก็เปิดดูได้ เหมือน `SIGNUP_TOKEN` ถ้าเจอสแปมให้เปลี่ยนทั้งใน `config.js` และ `save-log.gs` แล้ว Deploy ใหม่
- **ชื่อผู้บันทึกเชื่อได้เท่ากับระบบสมาชิก** ซึ่งไม่มีรหัสผ่าน (ดูข้อจำกัดในหัวข้อก่อนหน้า) — เหมาะกับการเก็บสถิติและสาธิต ไม่ใช่หลักฐานยืนยันตัวตน

### ดูสรุปในชีต

เปิดไฟล์ชีตแล้วใช้เครื่องมือของ Google Sheets ได้เลย เช่นสร้างแท็บใหม่แล้ววางสูตรนี้เพื่อดูข่าวที่ถูกบันทึกมากที่สุด

```
=QUERY('บันทึกข่าว'!H2:J, "select H, count(H) where H is not null group by H order by count(H) desc label count(H) 'จำนวนครั้งที่ถูกบันทึก'", 0)
```

หรือเลือกทั้งตารางแล้วกด **Insert → Pivot table** เพื่อดูรายคณะ / รายหมวด / รายคนได้

## ทดลองรันในเครื่อง

```powershell
node fetch-news.mjs        # ดึงข่าวล่าสุด
npx serve .                # เปิด local server แล้วเข้า http://localhost:3000
```

(เปิดไฟล์ index.html ตรง ๆ ไม่ได้ เพราะเบราว์เซอร์บล็อกการอ่าน news.json จาก file://)

## ทำให้อัตโนมัติ 100% (ฟรี)

1. push ขึ้น GitHub แล้วไปที่ **Settings → Pages** เลือก Deploy from branch `main`
2. GitHub Actions จะรัน `fetch-news.mjs` ทุก 1 ชั่วโมง, commit ข้อมูลใหม่, และหน้าเว็บอัปเดตเองโดยไม่ต้องทำอะไรเลย

## หมายเหตุเรื่องลิขสิทธิ์

เว็บนี้แสดงเฉพาะ**หัวข้อข่าว + ชื่อสำนักข่าว + ลิงก์กลับไปต้นทาง** (ข้อมูลจาก RSS ที่เปิดเผยเพื่อการเผยแพร่อยู่แล้ว) ไม่คัดลอกเนื้อหาเต็ม และให้เครดิตแหล่งที่มาทุกข่าว — ไม่ใช่เว็บไซต์ทางการของมหาวิทยาลัยขอนแก่น
